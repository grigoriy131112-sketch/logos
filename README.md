# Λ Логос

**Логос** — блог, чтобы делиться мыслями и публикациями.
Название взято с самого начала идеи: *логос* — это одновременно «слово»,
«мысль» и «смысл».

## Возможности

- Публикация текстов с разметкой **Markdown**;
- лента публикаций с кратким описанием, датой и временем чтения;
- **темы оформления**: тёмная и светлая, с запоминанием выбора и
  поддержкой системной настройки;
- **поиск** по заголовку, тексту и описанию без учёта регистра
  (включая кириллицу);
- темы (теги) с переходом по клику и облаком тем в боковой панели;
- **реакции** на публикации (❤️ 💡 🙏 🤔);
- комментарии — отклики читателей;
- страницы **авторов** и публикации отдельного автора;
- **«Случайная мысль»** — открыть случайную публикацию;
- **RSS-лента** — `/feed.xml` (в браузере выглядит как страница, читалки получают XML);
- **прогресс чтения** — полоса вверху страницы;
- кнопка «Скопировать ссылку» на публикации;
- страница «О блоге», страница 404;
- JSON API: `GET /api/posts` (поддерживает `?tag=` и `?q=`).

## Стек

Python 3, Flask 3, SQLite (стандартная библиотека), Markdown, чистый CSS/JS.
Никаких сборщиков и внешних сервисов — сайт запускается одной командой.

## Запуск

```bash
pip install -r requirements.txt
python seed.py      # необязательно: стартовые публикации
python run.py       # http://localhost:12000
```

Порт задаётся переменной окружения `PORT` (по умолчанию 12000).

## Проверка

```bash
python test_app.py
```

Скрипт прогоняет 22 сценария: главная, создание публикации, валидация,
API, поиск в разном регистре, фильтр по тегу, комментарий, реакции,
время чтения, авторы, случайная мысль, RSS (тип, дата RFC 822, автор,
стиль), «О блоге», 404.


## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | лента, фильтр `?tag=`, поиск `?q=` |
| GET | `/post/<id>` | публикация, реакции и отклики |
| GET/POST | `/new` | создание публикации |
| POST | `/post/<id>/comment` | добавить отклик |
| POST | `/post/<id>/react/<kind>` | поставить реакцию |
| GET | `/random` | случайная публикация |
| GET | `/authors` | список авторов |
| GET | `/author/<имя>` | публикации автора |
| GET | `/about` | о блоге |
| GET | `/feed.xml` | RSS-лента |
| GET | `/feed.xsl` | оформление ленты для браузера |
| GET | `/api/posts` | список публикаций в JSON |

## Заметка о поиске

SQLite `LIKE` не умеет сравнивать кириллицу без учёта регистра, поэтому
поиск по постам выполняется в Python через `casefold` (`app/db.py`).
Иначе запрос «Блог» не находил бы слово «блог».

## Заметка о RSS

Лента отдаётся типом `application/xml`, а не `application/rss+xml`:
Chrome не применяет XSLT (`/feed.xsl`) к типу `rss+xml` и показывает
сырой XML. RSS-читалки принимают `application/xml` нормально.
Ссылки строятся по `X-Forwarded-Proto` (см. `ProxyFix` в `app/__init__.py`),
поэтому за https-прокси они не уходят на http.

## Хостинг

Сайт живёт на GitHub Pages: <https://grigoriy131112-sketch.github.io/logos/>

Pages отдаёт только готовые файлы, поэтому в репозитории есть статическая
сборка. Её страницы рендерит само приложение, поэтому вид и текст совпадают
с живым сайтом, а ссылки ведут в подкаталог `/logos/`.

Что работает в статике: лента, публикации, темы, авторы, «О блоге», RSS,
тёмная и светлая темы, поиск по странице и «Случайная мысль».
Что требует сервера: публикация текста, отклики и реакции — вместо форм
показаны пояснения, а реакции остаются счётчиками.

Исходные данные лежат в `data/content.json` (публикации, отклики, реакции).
Пересборка после правки контента:

```bash
pip install -r requirements.txt
python tools/build_static.py
```

Результат — папка `docs/`, её отдаёт Pages (ветка `main`, каталог `/docs`).

## Заметка о подкаталоге

Сборка живёт в подкаталоге `/logos/`, поэтому пути к CSS, RSS и страницам
строятся с учётом `SCRIPT_NAME` (задаётся в `tools/build_static.py`).
Абсолютные адреса в `feed.xml`, `sitemap.xml` и `robots.txt` собираются
через `url_for(..., _external=True)`: так они верны и в корне домена,
и в подкаталоге.
