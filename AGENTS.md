# AGENTS.md — заметки о проекте «Логос»

## Что это
Блог «Логос» на Flask + SQLite. Название означает «слово/мысль/смысл».

## Команды
- Установка: `pip install -r requirements.txt`
- Наполнить примерами: `python seed.py`
- Запуск: `python run.py` (порт из `PORT`, по умолчанию 12000)
- Проверки: `python test_app.py`

## Устройство
- `app/db.py` — вся работа с SQLite. Таблицы `posts`, `comments`,
  `reactions`. Теги хранятся строкой через запятую.
- Поиск по постам идёт **в Python через `casefold`**, а не в SQL:
  SQLite `LIKE` не учитывает регистр кириллицы, из-за чего «Блог»
  не находил «блог». Не переносите поиск обратно в SQL без учёта этого.
- `app/routes.py` — маршруты; текст постов рендерится Markdown
  с расширениями `extra`, `sane_lists`, `nl2br` (без `html`, чтобы
  не исполнялся сырой HTML).
- Шаблоны — Jinja2, общий каркас в `templates/base.html`.
  Фильтры `ru_date`, `tags_list`, `reading_time`, `comments_count`
  регистрируются в `app/__init__.py`.
- Темы оформления — атрибут `data-theme` на `<html>`; значение хранится
  в `localStorage` (`logos-theme`) и применяется inline-скриптом в `<head>`
  до отрисовки, чтобы не было мигания. Палитры — CSS-переменные в
  `static/css/style.css` (`[data-theme="light"]` и `[data-theme="dark"]`).
- Даты хранятся в UTC в ISO-формате, выводятся фильтром `ru_date`.
  В RSS даты конвертируются в RFC 822 функцией `_rfc822` (`app/routes.py`).

## RSS
- `/feed.xml` — лента; `/feed.xsl` — XSLT-оформление для браузера.
- Лента отдаётся как `application/xml`: Chrome не применяет XSLT
  к `application/rss+xml` и показывает сырой XML.
- `ProxyFix` в `app/__init__.py` нужен, чтобы за https-прокси ссылки
  в ленте не строились по http.

## Соглашения
- Русский язык в интерфейсе и комментариях к коду.
- Сообщения об ошибках — через `flash` с категориями `error`/`success`.
- Новые маршруты регистрируются в `app/routes.py` (blueprint `blog`).
- База данных создаётся автоматически при старте приложения.

## Хостинг и статическая сборка
- Живой адрес: https://grigoriy131112-sketch.github.io/logos/
  Pages отдаёт ветку `gh-pages`; Pages не засыпает, в отличие от песочницы,
  поэтому это и есть постоянный хостинг.
- `.github/workflows/pages.yml` при пуше в `main` прогоняет `test_app.py`,
  пересобирает сайт (`tools/build_static.py`) и обновляет ветку `gh-pages`.
  Токен интеграции не может управлять Pages через API (`Resource not
  accessible by integration`) — поэтому публикация идёт через ветку.
- `tools/build_static.py` собирает `docs/` из `data/content.json`:
  страницы рендерит само приложение, поэтому вид совпадает с живым сайтом.
- Контент правится в `data/content.json`, после чего достаточно запушить
  `main` — workflow пересоберёт и опубликует сайт.
- Адреса страниц транслитерируются (`/tag/tekst/`, `/author/petr/`):
  кириллица в URL выглядит нечитаемо.
- Формы, которым нужен сервер (публикация, отклики, реакции), в статике
  заменяются пояснениями; поиск и «Случайная мысль» работают в браузере
  (`app/static/js/static.js`).
- Мастерская (`/workshop`, `app/static/js/workshop.js`) — профиль и свои
  мысли в `localStorage`, без регистрации. Работает и в статике: серверу
  ничего не нужно. В полной версии есть кнопка публикации в общую ленту
  (её скрывает сборка, выставляя `data-can-publish="false"`).
- Свой текст в мастерской экранируется до разметки, поэтому тег или
  скрипт в записи показывается как текст. Не заменяйте на вставку через
  `innerHTML` без экранирования.
- Правка и удаление публикаций в блоге: `/post/<id>/edit`, `/post/<id>/delete`
  (удаление чистит также `comments` и `reactions`). Валидатор общий —
  `_validate_post` в `app/routes.py`.
- Сайт живёт в подкаталоге `/logos/`, поэтому сборка задаёт
  `SCRIPT_NAME=/logos`, а абсолютные адреса строятся через
  `url_for(..., _external=True)`. Не заменяйте их на склейку с
  `request.url_root` — в подкаталоге получится двойной префикс.

## Безопасность
- Пользовательский Markdown рендерится без `html`-расширения.
- Файл базы `instance/logos.sqlite3` и `server.log` не попадают в git.
